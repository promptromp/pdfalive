# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

pdfalive is a Python (3.13 and 3.14; 3.14 is the development default) library and CLI tool that uses LLMs to enhance PDF files. It provides:
- **Automatic Table of Contents (bookmarks) generation** for PDFs using LLM inference, with optional postprocessing refinement
- **OCR processing** for scanned PDFs using Tesseract integration
- **Intelligent file renaming** using LLM inference for batch renaming with confidence scoring

## Development Commands

```bash
# Install dependencies (uses uv package manager)
uv sync

# Run the CLI - TOC generation
uv run pdfalive generate-toc input.pdf output.pdf --force

# Run the CLI - OCR text extraction
uv run pdfalive extract-text input.pdf output.pdf

# Run the CLI - Intelligent file renaming
uv run pdfalive rename -q "Rename to '[Author] - [Title].pdf'" *.pdf

# Linting
uv run ruff check .
uv run ruff format .

# Type checking
uv run mypy pdfalive

# Run tests
uv run pytest

# Run only the tests impacted by uncommitted changes, or by the current branch vs main
# (pytest-impacted; Rust-accelerated import parsing via the `fast` extra, detected automatically)
uv run pytest --impacted --impacted-module=pdfalive
uv run pytest --impacted --impacted-module=pdfalive --impacted-git-mode=branch --impacted-base-branch=main

# Evaluate TOC quality against golden data (free, replays recorded LLM responses)
uv run pdfalive eval --mode replay
```

## Architecture

The codebase follows a processor pattern where document operations are encapsulated in processor classes.

```
pdfalive/
├── cli.py                 # Click-based CLI entry point
├── console.py             # Consoles, progress bars and safe_text() for terminal output (shared by CLI and processors)
├── retry.py               # LLM retry policy: llm_retry() decorator, retryable-error predicate, retry warnings
├── structured_output.py   # Structured-output boundary: parsed answer or StructuredOutputError/ModelRefusalError, per-attempt usage
├── llm.py                 # Chat model construction (shared by CLI and eval runner)
├── tokens.py              # Token counting utilities
├── text.py                # Comparison forms that neutralize PDF extraction artifacts (shared by processors, models, evaluation)
├── paths.py               # Name keys and directory-entry identity (rename dedupe, collisions, case-only renames)
├── prompts.py             # LLM system prompts
├── config/
│   ├── __init__.py        # Config module exports
│   ├── models.py          # Pydantic models for config validation
│   └── loader.py          # TOML loading, path resolution, default_map conversion
├── evaluation/
│   ├── metrics.py         # Pure scoring functions (precision/recall/F1, page/level accuracy)
│   ├── cassette.py        # VCR-style LLM record/replay (RecordingChatModel, ReplayChatModel)
│   └── runner.py          # Eval case discovery and pipeline execution
├── models/
│   ├── toc.py             # TOC, TOCEntry, TOCFeature models
│   ├── page_content.py    # PageContent model
│   └── rename.py          # RenameOp, RenameResult, RenameInputs, RenameBatch, ResolvedRenames, ApplyRenamesResult models
├── processors/
│   ├── toc_generator.py   # TOCGenerator processor
│   ├── ocr_processor.py   # OCRProcessor for text extraction
│   ├── ocr_detection.py   # OCR detection strategies
│   ├── printed_pages.py   # Folio detection and PrintedPageMap (printed -> PDF page numbers)
│   └── rename_processor.py # RenameProcessor for file renaming
└── tests/                 # Unit tests

evals/                     # Evaluation data (repo root)
├── golden/<name>.json     # Ground-truth TOC per case (defines the case: pdf path, postprocess flag, entries)
└── cassettes/<name>.json  # Recorded LLM responses for replay
```

**CLI Commands:**
- `generate-toc` - Main command for TOC generation (with optional automatic OCR). Supports `--inplace` for modifying the input file directly, `--postprocess` for LLM-based TOC refinement, and `--ocr-output` to include the OCR text layer in the output PDF.
- `extract-text` - OCR-only command for text extraction from scanned PDFs. Supports `--inplace` for modifying the input file directly.
- `rename` - Intelligent file renaming using LLM inference. Supports reading paths from a file via `-f`/`--input-file` option for handling many files or long filenames. Use `-y`/`--yes` to skip the confirmation prompt. The inputs become a `RenameInputs`, whose constructor lists each file once (`pdfalive.paths.unique_input_paths()`: a file given more than once, in any spelling, counts once), so the "Renaming N file(s)" banner counts files; files sharing a name in different directories are separate inputs. Each LLM request lists its files as a JSON array of `{"file_id", "input_filename"}` entries numbered from `FIRST_FILE_ID` in every request (file names only, never directories; `ensure_ascii=False`, so non-ASCII names reach the model as text, with only unsafe characters in their visible escaped form via `pdfalive.console.visible()`, so a name with a newline cannot break out of its entry and the model never has to write a lone-surrogate escape back), and answers with both fields. Suggestions that cannot be applied safely are skipped and listed with the reason (see `RenameProcessor`); one whose id names no file of its request is shown by its id and the name it echoed. The preview and the skipped list show each input by `RenameInputs.display_names()`: its file name, or, for inputs whose names agree by name key, the resolved path relative to the directory those inputs have in common. The command owns the `TokenUsage` and passes it to `generate_renames(usage=...)` (required; the batches are its only return value), which records each LLM call as it completes, so the summary printed on every way out (in a `finally`: an aborted prompt, an error, a later batch failing) covers every call made. It exits with status 1 (`_EXIT_FAILURE`) when a confirmed rename fails, and under `--yes` when any suggestion was rejected, applied or not (nobody reads an unattended run's skipped list); no suggestions, or only ones keeping the current names (dropped, not rejected), is exit 0.
- `generate-toc` and `rename` print a token usage summary unless `--no-show-token-usage` is given (`show-token-usage` in the config file).
- `eval` - Evaluate TOC generation quality against golden data in `evals/golden/`. Modes: `replay` (default; serves LLM responses from a recorded cassette — free and deterministic), `record` (live LLM, writes the cassette), `live`. `--min-f1` / `--min-page-accuracy` provide CI threshold gating (exit code 1 on failure). Strict replay raises `CassetteMissError` when prompts have drifted since recording; `--loose-replay` replays by call order instead.
- All three LLM-using commands (`generate-toc`, `rename`, `eval`) accept `--reasoning-effort`; `extract-text` does not, since it makes no LLM calls.

**Processor Classes:**
- `TOCGenerator` - Extracts font/text features from PDF pages, sends to LLM for TOC inference, writes bookmarks back to PDF. Supports multiprocessing, intelligent batching for large documents, retry logic with exponential backoff, and optional postprocessing to refine the TOC using reference text from the document's first pages.
- `OCRProcessor` - Performs OCR on scanned PDFs using PyMuPDF's Tesseract integration. Supports multiprocessing for parallel page processing.
- `OCRDetectionStrategy` / `NoTextDetectionStrategy` - Strategy pattern for determining if a document needs OCR.
- `PrintedPageMap` - Maps printed page numbers to PDF pages using the folios printed on the pages (`page_folio_candidates()`: a line holding only a number, possibly decorated like `- 12 -` or `Page 12`, in one of the `_EDGE_ROWS` outermost rows of near-horizontal text at the top or bottom (so a per-page stamp line below the footer doesn't hide it), found relative to the page's own text rather than fixed y-positions and judged in display orientation for `/Rotate` pages; rows need a letter or digit, and numbers sharing a line with a running title are not read, as there they are mostly chapter numbers). Candidates are kept only when a page within `FOLIO_CONFIRMATION_WINDOW` implies the same offset; the longest run increasing in both PDF page and folio is the book's numbering sequence, and the map is empty unless it covers `MIN_FOLIO_PAGE_COVERAGE` of the pages. Contiguous off-sequence runs of at least `MIN_ALTERNATE_SEQUENCE_FOLIOS` sharing an offset (a separately numbered appendix, a second volume) make the printed pages they span ambiguous (never resolved). Between detected folios a printed page is interpolated linearly (exact when no page is missing in between, always monotone), strictly between the folios' pages; beyond the first/last folio the nearest folio's offset applies, within `MAX_FOLIO_EXTRAPOLATION`. Printed pages absent from the PDF (no page between two folios, or outside the document) are not located.
- `RenameProcessor` - Uses LLM to generate intelligent file rename suggestions based on user instructions. Supports batch renaming with confirmation preview. `generate_renames()` splits the files into requests (`_batch_files()`: each file costs its sent name's tokens plus `ENTRY_FRAMING_TOKENS` and `ESTIMATED_OUTPUT_TOKENS_PER_FILE` against `max_tokens_per_batch`, and the output estimates are capped by `DEFAULT_MAX_OUTPUT_TOKENS_PER_BATCH`; each entry is serialized once, by `_Request.files_array()`) and returns one `RenameBatch` per request: its suggestions and the files it listed, which its ids index (ids are per request, so positional numbering by the model is right by construction and no id can name another request's file). `resolve_renames(batches, inputs)` collapses identical repeated suggestions, rejects an id naming no file of its request, then (`_match_problem()`) differing suggestions for one file and an echoed `input_filename` that is not the file's name as sent (compared by name key), drops a suggestion that keeps the current name before the name checks (so it is never reported), rejects (`_copied_escape_problem()`) a new name with a backslash for a file whose name was sent with escapes (the model copying `\n` or `\xe9` into it as literal text, which looks identical in the preview), and plans a rename, within the source's own directory, only for a plain file name per `_target_name_problem()`: not empty, no surrounding whitespace, not `.`/`..`; a single part with no anchor per the running OS's path flavor (`_RUNNING_PATH_FLAVOR`: on POSIX `X: The Unknown.pdf` and a backslash are plain, on Windows they are paths); on Windows not `ntpath.isreserved()` (device names, a trailing dot or space, forbidden characters); no unsafe character (`pdfalive.console.contains_unsafe_characters()`, the definition the console escapes, plus `_INVISIBLE_NAME_MARKS`: U+200B, U+FEFF, U+2060, U+200E, U+200F, U+061C; ZWJ/ZWNJ stay allowed); and no leading dot unless the source has one. The function takes the path flavor as a parameter, so tests cover both OSes on either. It also rejects (`_collision_problem()`) two suggestions with the same target (the same new name in different directories is fine) and a target that is another input's entry (swaps and chains would depend on apply order), comparing `pdfalive.paths.entry_key()` values (the resolved path by name key, since `resolve()` keeps a directory's spelled case), each computed once; the source's own entry is excluded by counting it out, so an input that differs from the source only in case (another file on a case-sensitive volume) still collides. Each rejection carries a reason (`REJECTED_*` constants). `pdfalive.paths.unique_input_paths()` treats two input paths as one only when they are the same file (`os.lstat`, so a symlink is separate from its target) at the same entry by name key (so hard links stay separate, and so do `Foo.pdf`/`foo.pdf` on a case-sensitive volume). `apply_renames()` never replaces an existing entry (`os.path.lexists`, so a dangling symlink counts): the only exemption is a case-only rename (`pdfalive.paths.is_case_only_rename()`): names agree by name key, the target's exact name is missing from `os.listdir()` of the directory (a listed name is an entry of its own: a hard link `INPUT.PDF` beside `input.pdf` on a case-sensitive volume, where `rename()` would do nothing while reporting success), and `os.lstat` finds the source's own entry there, never following symlinks (following them let a symlink be renamed over the file it points to). A hard-linked file can be case-renamed. Tests for either kind of file system skip on the other; Linux CI runs the case-sensitive ones, and `pytest --basetemp=<dir on a case-sensitive volume>` runs them on macOS. Each file's rename is attempted on its own: any exception is reported for that file and the rest continue. Known limitation: another process creating the exact target between the existence check and the rename would have it replaced; the stdlib has no portable no-replace rename. `RenameOp` (`file_id`, `input_filename`, `output_filename`, `confidence`, `reasoning`) is a frozen pydantic model, so the resolved-rename dataclasses holding it are hashable.

**Model Classes:**
- `TOC` / `TOCEntry` - Pydantic models for structured LLM output with confidence scores (`PostprocessedTOC` / `PostprocessedTOCEntry`: the postprocessor's schema, adding `printed_page`). `TOC.sanitize_hierarchy()` clamps levels for PyMuPDF compatibility. `TOC.partition_by_page_range()` separates entries whose page lies outside the document (PyMuPDF's other `set_toc()` constraint). `TOC.sort_by_page()` enforces page number monotonicity after postprocessing. `TOC.deduplicate()` and `TOC.merged()` (which `_extract_toc_paginated()` calls once, after all batches) treat two entries on the same page as one bookmark when their titles are equal, or when at least one carries an extraction artifact and their `pdfalive.text.identity_form()` (artifact-neutral, without apostrophes) is equal: `Kähler`/`K¨ahler` and `O'Neill`/`O´Neill` collapse, while two artifact-free titles are never equated by stripping diacritics (`ẋ`/`ẍ`, `Kähler`/`Kahler`), and case, punctuation and symbol differences (`Case x > 0` / `Case x < 0`) stay distinct. A duplicate keeps the first entry's page, level and confidence and takes only a clean title from a later spelling.
- `TOCFeature` - Compact representation of page features sent to the LLM
- `PageContent` - Data model for page representation
- `RenameOp` / `RenameResult` - Pydantic models for file rename operations with confidence scores and reasoning
- `RenameInputs` - The files to rename, each once in input order; the constructor enforces it (`pdfalive.paths.unique_input_paths()`), and `display_names()` says how to show each input so same-named ones can be told apart
- `RenameBatch` - One LLM request's suggestions with the files it listed; `path(file_id)` resolves the request's own 1-based ids
- `ResolvedRenames` / `PlannedRename` / `RejectedRename` - Dataclasses for suggestions resolved against the input files: the renames to apply (source and target paths) and the rejected ones with their reasons
- `ApplyRenamesResult` / `RenameError` - Dataclasses tracking successful and failed rename operations

**Key Integration Points:**
- PyMuPDF (`pymupdf`) for PDF reading/writing and OCR via Tesseract
- LangChain for LLM abstraction with `init_chat_model()` and `with_structured_output()` for typed responses
- LangSmith for observability/tracing via `@traceable` decorator on CLI commands
- Tenacity for retry logic with exponential backoff. One policy, in `pdfalive/retry.py`, covers every LLM call: both processors ask for structured output with `include_raw=True` and make each call through `pdfalive.structured_output.invoke_structured_with_retry(console, model, messages, schema, usage=..., description=..., input_tokens=...)` directly (no processor-level wrapper), which applies `invoke_with_retry()` (it reports the call and its duration under `llm_retry(console)`) to `invoke_structured()`, the one structured-output boundary. `invoke_structured()` accepts only include_raw answers (anything else is a `TypeError`: the model was asked wrongly), records each attempt's token usage in the caller's `TokenUsage` as the answer arrives (billed whether or not it parses: the raw message's `usage_metadata`, else tiktoken estimates, measuring the parsed model by its repr since JSON rejects the lone surrogates of undecodable file names), returns the parsed model, and otherwise raises: `StructuredOutputError` (defined in `retry.py`) for a recorded parsing error, no parsed result, one of the wrong type, or a pydantic `ValidationError` the call itself raises (the OpenAI SDK validates its own structured outputs; that attempt is recorded with estimated input and unknown output); `ModelRefusalError` for a refusal (OpenAI's `OpenAIRefusalError`, looked up in `sys.modules` only once something has imported the integration, or an Anthropic `refusal` stop reason); `TruncatedAnswerError` for an Anthropic `max_tokens` stop, the counterpart of OpenAI's `LengthFinishReasonError`. Refusals and truncations are not retried, since they would recur. Any other error `model.invoke()` raises passes through to the policy. Up to `MAX_RETRY_ATTEMPTS` (5) attempts, of which at most `MAX_PARSE_ATTEMPTS` (3) may fail to parse: `AttemptLimit`, the stop condition, counts unparsed answers across the call's attempts (restarting at each call's first attempt), so the bound holds however transient failures interleave and a parse failure after transient ones still gets its retries; the retry warning shows `attempt n/5` plus `unparsed answer k/3`. The wait before retry n is `RETRY_INITIAL_WAIT_SECONDS` * 2^(n-1), i.e. 10, 20, 40 and 80 s, and a provider's `retry-after-ms` or `Retry-After` hint (each parsed on its own, so a malformed one does not hide the other) lengthens a wait up to `RETRY_MAX_WAIT_SECONDS` (120 s). `is_retryable_error()` is an allowlist of transient conditions: a LangChain `ModelError` whose `is_retryable` is true (the OpenAI and Anthropic integrations raise these, so their own classification is used when present; those SDKs use httpx2 and wrap its transport errors, which LangChain wraps again as `ModelConnectionError` / `ModelTimeoutError`, so no httpx2 error reaches the policy unwrapped), an Ollama `ResponseError` with its -1 no-status sentinel (a server error mid-stream; looked up in `sys.modules` like the OpenAI refusal), HTTP 408/409/429/5xx read from `status_code` or `response.status_code` (`httpx.HTTPStatusError`; a status outside 100-599 counts as none), status-less connection failures and timeouts (built-in `ConnectionError` / `TimeoutError`, httpx network and timeout errors, which the Ollama client raises), and `StructuredOutputError` (classified by pdfalive's own type: a `ValidationError` raised anywhere else is not retried). Everything else surfaces on the first attempt: other 4xx (context overflow, an unsupported reasoning effort, credentials), a 429 whose `code` is `insufficient_quota` (`_INSUFFICIENT_QUOTA_CODE`: waiting does not refill a quota), programming errors, a truncated completion, a refusal, a cassette replay miss (`CassetteMissError`), and non-`Exception`s, so Ctrl-C during an LLM call stops the program. The predicate, the wait and `describe_exception()` never raise. `invoke_with_retry()` raises `LLMCallError` (from the last error) for any `Exception` the policy gives up on; Ctrl-C and `SystemExit` pass through unwrapped. `generate-toc`, `rename` and `eval` report it with `_llm_failures_reported()`: an `Error:` line and exit status 1 (`_EXIT_FAILURE`), not a traceback. For OpenAI and Anthropic it is the only retry layer: `build_chat_model()` passes `max_retries=0` to exactly the providers in `_SDK_RETRIES_OFF`, resolving the provider from an explicit `provider:model` prefix or the model-name prefixes LangChain infers those two from (`_PROVIDER_MODEL_PREFIXES`). Known limitations: those prefixes mirror LangChain's private `_attempt_infer_model_provider()` (there is no public API), so a prefix LangChain adds later is treated as an unknown provider, which keeps its SDK retries (double retry, never a wrong setting); and switching the SDK retries off trades their sub-second retry of a dropped keep-alive connection for one predictable layer whose first wait is 10 s. Any other provider gets no extra setting and keeps its SDK's own behavior: Ollama's client has no retries, and a provider whose SDK retries is retried by both layers. `_check_output_choice()` validates OUTPUT_FILE against `--inplace` with `is not None`, as `_output_destination()` decides, so an empty OUTPUT_FILE is a usage error rather than a write to ""; the `--inplace` temp file is created and removed by the `_output_destination()` context manager, so no way out of either command leaves one behind.
- Rich for terminal progress indicators and table output, all through `pdfalive/console.py`. Text pdfalive does not control (file paths, model identifiers, OCR language codes, eval case names, TOC titles, LLM rename suggestions and reasoning, exception messages) reaches the terminal exactly as it is. It is never parsed as markup or for `:name:` emoji shortcodes (`[van Author] Some Title.pdf` would lose `[van Author]`, a stray `[/]` raises `MarkupError`); `rich.markup.escape()` is deliberately not used, since separately escaped fragments can pair up into a tag once joined (`[x` ... `y]`) and it mishandles trailing backslashes. Characters that would act on the terminal or the displayed line are replaced by Python-style escapes shown in `ESCAPE_STYLE` (so a real ESC, shown `\x1b`, cannot be mistaken for a literal backslash sequence): control characters (C0, DEL, C1), bidi embedding/override/isolate controls and line/paragraph separators (U+202A-U+202E, U+2066-U+2069, U+2028, U+2029; an RLO can disguise `invoice\u202efdp.exe` as a PDF; other format characters such as soft hyphens and zero-width joiners are kept), and lone surrogates (an undecodable byte 0xE9 from argv or a file name, shown `\xe9`, which would otherwise crash a UTF-8 terminal). A single-line value also has newlines and tabs escaped; a multi-line value (exception descriptions, the token summary) keeps newlines, with CRLF normalized to LF. Two choke points apply the rules: `create_console()` returns a `TerminalConsole`, whose `render_str()` handles every printed string and plain-string table cell (markup and emoji forced off, newlines kept), and `safe_text(*parts, multiline=False)` composes styled `Text` from plain and `(text, style)` parts, the single point where outside text becomes `Text`. `visible()` is the plain-string form, used for Click error messages (Click prints those itself), and `truncate_visible()` cuts a value to a cell width measured on its shown form, so an escape is never cut in half (rename-preview reasoning). `contains_unsafe_characters()` exposes the same single-line definition to checks outside the console (rejecting a suggested file name). Program styling uses `style=` or `safe_text()`, never markup tags. Progress bars come from `create_progress(console)`, whose description column renders plain text (`markup=False`). Ruff's banned-api rule (TID251) rejects, outside `pdfalive/console.py` (tests are exempt): `rich.console.Console` (annotate with `pdfalive.console.ConsoleType`, a non-callable alias), the global-console helpers `rich.print`, `rich.print_json`, `rich.inspect`, `rich.get_console` and `rich.reconfigure`, the `rich.progress`, `rich.live`, `rich.status`, `rich.prompt`, `rich.logging`, `rich.traceback` and `rich.pretty` modules (whose APIs fall back to Rich's unconfigured global console when none is passed), and the markup and ANSI parsers `rich.markup`, `Text.from_markup` and `Text.from_ansi`. It cannot reject a bare `Text(...)` built from outside text, which is why the rule below names `safe_text()`. `TokenUsage.summary_text()` returns the token summary as `Text`; `TokenUsage.print_summary(console=None)` prints it, on a `create_console()` console when none is given. Retry warnings for both LLM-calling processors come from `pdfalive/retry.py` (`retry_warning()`, and `describe_exception()`, which never raises because it runs inside tenacity's `before_sleep` callback: an exception whose `__str__` raises falls back to its type name, and a `message` attribute is compared against `None` only, never tested for truth, then converted with `str()`, so array-like values work).
- Default model: `gpt-5.6` (configurable via `--model-identifier`)
- Optional reasoning effort via `--reasoning-effort` / `reasoning-effort`, built in `pdfalive/llm.py`'s `build_chat_model()`. `reasoning_effort` is the parameter name OpenAI, Anthropic and LangChain all share, so one value covers every provider that has the control; providers without it (Ollama) ignore it. The value is deliberately NOT validated client-side, because accepted levels differ per model rather than per provider (`gpt-6-sol`/`gpt-6-luna`: none/low/medium/high/xhigh; `gpt-6-astra`: the same minus `none`; Anthropic also offers `max`). Providers reject a bad level with an error naming the ones they accept, and since that is a 400 the retry policy surfaces it immediately. When unset the kwarg is omitted entirely rather than passed as None, so provider defaults are untouched for anyone who does not opt in.

**TOC Generation Strategy:**
The `TOCGenerator._extract_features()` method extracts font metadata (name, size) and text snippets from the first few blocks/lines of each page (Phase 1), then scans remaining blocks for heading candidates (Phase 2, with stricter font size threshold of 1.2x body size and a cap of 3 candidates per page, checking only the first span per block). Phase 2 uses a `font_size_ratio` parameter on `_is_heading_candidate()` to decouple the size-based check (which uses the explicit ratio) from the bold-based check (which always uses the true `body_font_size`). For spans in the bottom 40% of a page (y > `_BOTTOM_OF_PAGE_Y_THRESHOLD` = 0.6), Phase 2 applies relaxed criteria (Phase 1's 1.15x ratio instead of 1.2x) to catch section headings that start near the end of a page — these would otherwise be missed, causing the LLM to misattribute the section to the next page's running header. Font subset prefixes (e.g. `ABCDEF+`) are stripped for deduplication. Before the LLM call, `filter_features_for_llm()` shrinks the payload by keeping all heading-like spans (via `_is_heading_like_feature()`, mirroring the extraction criteria on TOCFeature objects) plus the first body span per page (preserving page anchoring, the body-font baseline, and the running-header y-position signal) — a ~55% feature-token reduction on a 400-page book. The full unfiltered features are still used for the deterministic corrections and the postprocess summary. Features are serialized into a compact pipe-delimited format with a font table (`serialize_features_compact()`), which is ~50% more compact than Python `str()` — font names are mapped to short IDs (F0, F1, ...), spans are grouped by page (`P42:\nF0|14|Chapter Title|.12|B`), and redundant fields like `text_length` are omitted. This format is sent to the LLM which identifies chapter/section headings and returns structured `TOCEntry` objects with confidence scores. Both first-pass prompts (initial and continuation) require the heading's printed numbering to be kept in the title even when the number arrives as a separate span from the title text (`CHAPTER` / `1` / `Distance and Angles` -> `Chapter 1: Distance and Angles`); the postprocessor prompt repeats the rule. For large documents, features are batched with overlap for context continuity (default 100K tokens per batch). Note a depth-cap mismatch between the two passes: the first pass instructs the LLM to "Limit the TOC to a maximum depth of {max_depth} levels" (`DEFAULT_MAX_TOC_DEPTH` = 2), while `TOC_POSTPROCESSOR_SYSTEM_PROMPT` carries no depth cap at all. The final hierarchy depth is therefore not deterministic — repeated runs of the same model on the same book produce two-level or three-level output from draw to draw, which is why `level_accuracy` swings between ~0.28 and 1.00 on `arnold` with no code change and is not yet usable as a regression gate. Token counting uses tiktoken (`o200k_base` encoding) for accurate tokenizer-based counts, eliminating the need for character-based ratio estimation. LLM calls go through the shared retry policy (`pdfalive/retry.py`), which only retries transient errors (rate limits, server errors, timeouts, malformed structured output); client errors like context overflow are raised immediately. All deterministic title matching after the LLM call (the running header correction, printed-TOC offset detection, the postprocess placement's first-pass matching, and `_find_heading_page()` verification) compares keys built from `pdfalive.text.matching_form()`. Each title is converted once: an entry's title is prepared as a `_HeadingTitle` (search keys, numbers, section prefix and title key, all from one `matching_form()` call), which the postprocess placement (its `_OriginalEntryMatcher` lookups and `_verify_heading_page()`), the page searches (`_find_heading_page()`, `_page_has_heading_in_bottom()`) and the running header correction share, and whose `is_matchable()` holds the key-length rules; `_OriginalEntryMatcher` computes each original entry's title key, designator-stripped core and digits once, and front-matter detection converts each candidate title once. `matching_form()` neutralizes PDF text-extraction artifacts by removing accents from both sides rather than guessing where a spacing accent belongs: it expands the Latin ligature glyphs (U+FB00–U+FB06), applies NFD, removes an explicit set of TeX spacing accents (diaeresis, acute, circumflex, tilde, macron, breve, dot, ring, double acute, cedilla, ogonek, caron, plus the modifier-letter accents U+02C6/02C7/02C9/02CA/02CB) together with any whitespace a span break left beside them (`K ¨ahler`), dotting a dotless ı/ȷ that an accent extracted before its letter was set over (not one after a cedilla or ogonek, which extraction places after their letter: `Kas¸ık`), drops combining diacritics (U+0300–U+036F) only from Latin letters, and applies NFC and casefold. The ASCII `^`, `~` and backtick are notation and are not treated as accents. So extracted `Deﬁnitions`, `K¨ahler`, `Poincar´e`, `C¸etin` or `O´Neill` match `Definitions`, `Kähler`/`Kahler`, `Poincaré`/`Poincare`, `Çetin` and `O'Neill` wherever extraction placed the accent, while super- and subscripts (`S²`, `H₁`), kana voicing marks, Cyrillic `й`/`ё`, Greek accents, marks on symbols (`≠`, `∉`) and symbols such as `™` keep their identity. Length thresholds such as `_FUZZY_MIN_SUBSTRING_LEN` are measured on the matching keys. Matching keys are only ever compared: features, reference text, prompts and bookmark titles keep their original spelling. The matching does, however, decide values that reach the postprocess prompt: the running header correction's page numbers and multi-batch `TOC.merged()` deduplication (both applied to the TOC the prompt lists), and the front-matter offset note. Better matching can therefore change that prompt on books with such artifacts. After the LLM generates the TOC, a deterministic running header correction step (`_correct_running_header_pages()`) detects entries whose title appears only at running header position (y < 0.05) in the features and, when the title is found in the bottom half of the previous page (via feature index or PDF text search fallback), corrects the page number. This requires no additional LLM calls. When `--postprocess` is enabled, a second LLM pass refines the TOC by cross-referencing against any printed table of contents found in the document's first pages (up to 20 pages scanned, with pages 4+ filtered to keep only TOC-like lines: dot-leader entries, section numbers, and short title lines), removing duplicates, fixing typos, and adding missing entries. The features summary for the postprocessor prioritizes heading-like spans (80% budget) over body text, capped at 80 entries. The postprocessor prompt explicitly instructs the LLM to output PDF page numbers (not printed page numbers), with a conversion formula when front matter offset is detected. After postprocessing, a deterministic correction step restores original PDF page numbers for matched entries (using best-match fuzzy matching with a coverage ratio threshold to avoid false substring matches) and applies running-header-aware offset correction for new entries via `_find_heading_page()`, which searches a window around the entry's page for the heading text in non-running-header positions (y >= 0.06), avoiding false matches from chapter running headers that appear on every page within a chapter. The postprocessor's structured-output schema is `PostprocessedTOC` (first pass: `TOC`); its entries (`PostprocessedTOCEntry`) also report, for each entry listed in the printed TOC, the page number printed there (`printed_page`), copied verbatim rather than converted; a non-Arabic value (e.g. roman front-matter numerals from providers without strict schema enforcement) is read as absent. Each pass calls the LLM through `invoke_structured_with_retry()` (`pdfalive/structured_output.py`) with its own schema (`TOC` for the first pass, `PostprocessedTOC` for postprocessing; `TOCGenerator._structured_model()` builds each schema's structured-output model once), and an answer that does not parse into the requested schema is a `StructuredOutputError` under the shared retry policy. Each refined entry is then placed exactly one way, by the strongest evidence available: an exact first-pass match keeps its first-pass page (the heading was seen there; when the entry's printed page is located, only within `_MAX_FOLIO_MATCH_DISTANCE` of it, since farther away the same title is a different occurrence); otherwise an entry citing a printed page is placed through `PrintedPageMap`, which maps printed page numbers to the PDF pages actually carrying them; otherwise a fuzzy (prefix) first-pass match; otherwise the postprocessor's estimate is kept. Matching (`_OriginalEntryMatcher`) is one-to-one: exact matches are assigned globally, nearest position first (the folio-mapped page when available), before any fuzzy match, so a title repeated per chapter ("Exercises") is neither collapsed onto one original occurrence nor stolen by a far copy; an exact-title repeat left over once every same-title original is claimed, with nothing else locating it, is dropped as the postprocessor repeating an entry. This replaces trusting the LLM's `printed + offset` arithmetic, whose single global offset drifts when a PDF omits or inserts pages relative to the printed book (the `offset-drift` eval case drifts from +13 at the first chapter to −11 at the index, which pushed back matter past the last page). The folio map is built lazily (`TOCGenerator._printed_page_map`, one pass over all pages) only when an entry cites a printed page, and an unusable map is reported on the console. The folio scan reads pages text-only (`TEXTFLAGS_DICT & ~TEXT_PRESERVE_IMAGES`: identical lines and spans without image payloads, ~35x faster on scanned books); heading searches keep the default extraction, since dropping image blocks can merge the text blocks on either side of an image. Finally, a verification pass applies `_find_heading_page()` (via `_verify_heading_page()`) to ALL entries, including folio-placed ones — a heading found on a page outranks every page source, and the LLM sometimes misreads the printed TOC's page number (on the `mitrinovic` draw, skipping verification for folio-placed entries cost two pages), searching outward from each entry's current page (±offset window) so the closest match wins — this catches cases where the initial extraction was wrong and the postprocessor restored the wrong page. An entry claimed past the last page is searched around the nearest in-document page (the last page), and `_find_heading_page()` orders the search range itself by distance from the hint, so a hint outside the range still searches every in-range page. Front matter title detection uses a regex pattern (`_FRONT_MATTER_TITLE_PATTERN`) that recognizes titles like "Introduction" and "Preface to the Second Edition" as front matter, while correctly excluding subject-specific titles like "Introduction to Ito-Calculus". After correction, `TOCGenerator._drop_out_of_range_entries()` drops (and reports) any entry whose page lies outside 1..page_count. PyMuPDF's `set_toc()` validates pages only loosely — it raises "page number out of range" for rows outside -1..page_count (which previously crashed the run after all LLM work), but never checks the final row (silently clamping it to the last page) and maps page 0 to page 1 — so such entries are dropped rather than left to point at unrelated content. Then `TOC.sort_by_page()` enforces page number monotonicity, and finally `TOC.sanitize_hierarchy()` clamps hierarchy levels to satisfy PyMuPDF constraints (first entry must be level 1, no level jumps > 1).

**In-place Editing:**
Both `generate-toc` and `extract-text` support `--inplace` mode which modifies the input file directly. This uses a temporary file strategy (write to temp, then replace original) to work around PyMuPDF's limitation of not being able to save to the same file it has open. Original file permissions are preserved.

**OCR Integration:**
When `--ocr` is enabled (default), `generate-toc` automatically detects if a PDF needs OCR by checking for extractable text (using configurable `min_text_coverage` threshold, default 25%), performs OCR if needed, then proceeds with TOC generation on the text layer. By default the OCR text layer is discarded from the final output (used only for TOC inference); use `--ocr-output` to include it.

**Configuration System:**
The CLI supports TOML configuration files (`pdfalive.toml` or `.pdfalive.toml`) for setting default option values. The config module (`pdfalive/config/`) handles:
- `models.py` - Pydantic models for validating config structure with kebab-case alias support
- `loader.py` - File discovery (cwd > home > ~/.config/pdfalive/), TOML parsing, and conversion to Click's `default_map` format

The config is loaded via an eager callback on the `--config` option in `cli.py`. Global settings apply to all LLM-using commands, and command-specific settings override globals. CLI arguments always take precedence over config file values.

**Evaluation Harness:**
The `pdfalive/evaluation/` package measures TOC generation quality against golden (ground truth) data. A case is fully defined by `evals/golden/<name>.json` (source PDF path resolved relative to the evals dir's parent, a `postprocess` flag, and the expected entries). `metrics.py` contains pure scoring functions: golden and generated entries are greedily matched by normalized-title similarity (threshold 0.8, page distance as tiebreaker for repeated titles like "Exercises"). Matching is tolerant of dropped section numbering: a pair that agrees only after `strip_section_prefix()` removes leading numbering ("Chapter 1: Distance and Angles" vs "Distance and Angles") still matches, scored at 0.95x so exact full-title matches always pair first — without this, one model's choice to omit a printed chapter number is charged twice, as both a missing golden entry and a spurious generated one. `normalize_title()` starts from the same `pdfalive.text.matching_form()` the pipeline uses, with its own punctuation policy (apostrophes join words, other punctuation becomes a space), so a generated title that differs from the golden only by an extraction artifact or a Latin accent (a copied `K¨ahler` or `Eﬃciency`, or `Poincare` for `Poincaré`) pairs at similarity 1.0. Otherwise such a difference on a short title can fall below the threshold and be charged twice, the same way a dropped section number would be. Scoring yields precision/recall/F1, page accuracy (exact and within ±N pages), and level accuracy. `cassette.py` provides VCR-style record/replay: `RecordingChatModel` wraps a real LLM and persists each structured response (with a SHA-256 request fingerprint) to `evals/cassettes/<name>.json` after every call; `ReplayChatModel` serves them back in order with zero network calls, validating each recorded response against the requested schema (and its recorded schema name) before advancing its cursor: a mismatch raises `CassetteMissError`, which the retry policy never retries, so a miss cannot make a retry consume the next call's response. Both duck-type the `with_structured_output(schema).invoke(messages)` interface that processors use. Strict replay (default) fails loudly on prompt drift — re-record the cassette when prompts/features change intentionally. Cassettes also store each call's `usage_metadata`, so replays report the recorded run's real token usage. The eval runner does not perform OCR: scanned books are pre-OCR'd once (`pdfalive extract-text`) into local copies (e.g. `data/ocr/`, gitignored) and the golden's `source_pdf` points at the OCR'd copy. The golden TOCs for `geometry` and `arnold` are human-verified (arnold: pipeline output corrected against page text). Arnold intentionally scores <1.00 until known pipeline defects are fixed. Benchmarking across models and repeated samples showed three that reproduce in every run: 'Appendix 11 Short wave asymptotics' (golden p455, pipeline p453), 'Appendix 14 Poisson structures' (golden p473, pipeline p477), and a spurious level-1 'Bibliography...' entry at p520 that the golden lacks — that last one looks like a real heading the golden omits rather than a pipeline error. The same-title chapter/subsection pair 'Chapter 7 Differential forms' vs '§34 Differential forms' is the case `strip_section_prefix()` must not collapse, and is covered by a metrics test. The `mitrinovic` golden was seeded from prior bookmarks; depending on the recorded draw, the LLM misreads an occasional printed-TOC page, which heading verification corrects. The `offset-drift` golden (a text PDF) is human-verified from the document's printed Contents, every numbered entry located two independent ways (heading text on the page and on-page folios); it is the regression case for printed-to-PDF offset drift, and its cassette is a draw in which the LLM's page estimates drift (page accuracy 0.58 without printed-page placement, 1.00 with it). Cassettes are recorded with the default model (`gpt-5.6`). Note that a cassette captures one draw from a high-variance distribution — first-pass entry counts vary substantially between runs with everything else held fixed — so the replay baseline is a fixed reference for testing post-LLM logic, not a stable measure of model quality. In particular `arnold`'s level accuracy reads 0.28 for a two-level draw and 1.00 for a three-level one against the golden's three-level hierarchy, depending on which draw is recorded; see the depth-cap mismatch noted above.

## Development Guidelines

- After making major changes to functionality, CLI options, or project architecture, always review and update all documentation to stay in sync: `README.md`, `docs/usage.md`, and `CLAUDE.md`. Docs should accurately reflect current defaults, option names, and feature descriptions.
- When adding or removing CLI configuration options, also update the example `pdfalive.toml` snippets in `README.md` and `docs/usage.md`, as well as the config models in `pdfalive/config/models.py`.
- When printing through Rich: build every message or table cell that includes text the program does not control with `pdfalive.console.safe_text()` (pass `multiline=True` only for genuinely multi-line values), never `Text(...)` or `Text.assemble(...)`; style program text with `style=` (consoles never parse markup, so tags print literally); pass outside text in Click error messages through `visible()`; create consoles and progress bars with `create_console()` and `create_progress()` (ruff TID251 enforces the Rich imports, not the `safe_text()` rule). Regression tests use the shared fixtures in `pdfalive/tests/conftest.py`: `markup_like_filename` for file paths (hostile names that are still valid single path components on every OS), `markup_like_text` for every other value (adds `[/]`, URL link tags, emoji shortcodes and trailing backslashes), `control_sequence_text` for characters that act on the terminal or the line (control sequences, newline, tab, an RLO spoof, an undecodable byte), and `recording_console`, a `TerminalConsole` that records a module's output.
- always prefer placing imports at top of files rather than inline. Especially when writing unit-test. only do otherwise to avoid circular dependencies in rare cases. In those cases, mention explicitly why you are doing this in a comment on the relevant code line.
- Tests run isolated from the developer's home directory: the autouse `isolated_home` fixture in `pdfalive/tests/conftest.py` points it at an empty temporary one (and returns it, for tests that write a home config), so config discovery never reads a real `~/pdfalive.toml`.
- When writing unit-tests, use variables and/or pytest fixtures (e.g. via conftest.py and `@pytest.fixture` decorator) for fixture values and objects, rather than repeating literal values in test setup and assertions. Prefer using pytest's `@pytest.mark.parametrize` decorator when you wish to test different values or combinations of values rather than creating repetitive standalone test cases.
- The test suite runs with LangSmith tracing disabled (`pytest_configure` in `pdfalive/tests/conftest.py` turns it off through the environment for the whole session, covering threads and subprocesses): the CLI commands are `@traceable`, so with a developer's `LANGSMITH_TRACING` set every CLI test would otherwise post a trace and consume the LangSmith project's quota. Keep it that way for new tests.
- When making changes, always make sure formatting, linting, type checks, and tests work afterwards. We use ruff, mypy and pytest for these, and can run them via uv, e.g. `uv run ruff ...`, `uv run mypy`, etc.
- Bumping `pymupdf` (or anything else that affects PDF text/font extraction) changes the features sent to the LLM and therefore the prompts, which invalidates the eval cassettes even though no code changed. Always run `uv run pdfalive eval --mode replay` after a dependency bump; if strict replay fails, `--loose-replay` tells you whether the post-LLM logic is still intact, and `--mode record` re-records.
- When changing TOC generation heuristics, feature extraction, prompts, or correction logic, run the evaluation harness (`uv run pdfalive eval --mode replay`) and compare metrics before/after. If a change intentionally alters LLM prompts, re-record cassettes with `--mode record` (costs real LLM calls) and re-verify the golden data still scores well.
- When finished making substantial changes to functionality and/or API (e.g. CLI usage) make sure to update documentation - README.md, CLAUDE.md and docs/ markdown files should all be kept up to date. Changing any CLI configuration options should also result in update the config/ submodule which lets us use TOML configuration files for defaults.
